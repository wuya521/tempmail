# 管理员建号与接码邮箱说明

本文说明如何实现：**一次操作得到「可登录的 `api_key` + 已存在的随机临时邮箱」**，供顾客用你的站点接收验证码（如 Claude 等服务的邮件验证）。

---

## 1. 功能是什么？

| 概念 | 说明 |
|------|------|
| **目标** | 新用户拿到 **一把 `api_key`**，用它在你的网页上登录后，**账户里已经有一个**可用的临时邮箱地址，可直接收信、接码。 |
| **对应关系** | 本次请求生成的 **`full_address`** ⇔ 返回的 **`api_key`** ⇔ 顾客登录后看到的**同一个邮箱**。 |
| **与管理员自己建邮箱的区别** | 若用管理员 Key 调用 `POST /api/mailboxes`，邮箱挂在**管理员账号**下；本功能邮箱挂在**新注册的普通用户**下，适合交付给顾客。 |

实现方式：调用 **`POST /api/admin/accounts`**，并在 JSON 中传入 **`mailbox_domain`**（见下文）。

---

## 2. 前置条件

1. **服务已更新**：服务器已 `git pull` 并重新构建、启动 API 容器（包含 `mailbox_domain` 逻辑的版本）。
2. **至少一个已激活域名**：在管理后台「域名」中，存在状态为**激活**的域名（例如 `mail.yahoohh.chat`）。`mailbox_domain` 必须与这里登记的域名**完全一致**（含子域）。
3. **管理员 API Key**：形如 `tm_admin_...`，仅用于你本机脚本或可信环境，**勿发给顾客**、勿提交到公开仓库。

---

## 3. 推荐用法：管理员 API 一次建号 + 邮箱

### 3.1 接口

- **方法 / 路径**：`POST /api/admin/accounts`
- **鉴权**：`Authorization: Bearer <管理员API_Key>`
- **Content-Type**：`application/json`

### 3.2 请求体

| 字段 | 必填 | 说明 |
|------|------|------|
| `username` | 是 | 新用户名，2～64 字符，**全局唯一**。 |
| `mailbox_domain` | 否 | 填写后：在该**已激活**域名下自动创建一个邮箱，本地部分**随机**；与全局已有地址冲突时会**自动换随机串**重试。 |
| （不传 `mailbox_domain`） | — | 仅创建账号并返回 `api_key`，**不**自动创建邮箱；顾客需自行 `POST /api/mailboxes` 或由你后续代建。 |

### 3.3 成功响应（HTTP 201）

- `id`、`username`、`api_key`：新用户标识与登录用 Key。
- `mailbox`：当传了 `mailbox_domain` 且创建成功时，内含 `id`、`full_address`、`created_at` 等；顾客收信用 **`full_address`**。
- 若账号已创建但邮箱创建失败（极少见）：`mailbox` 可能为 `null`，并带 `mailbox_error` 说明原因。

### 3.4 curl 示例

```bash
BASE="https://你的域名或IP:端口"   # 注意 API 若经反代，用对外 HTTPS 地址
ADMIN_KEY="tm_admin_你的管理员Key"

curl -s -X POST "$BASE/api/admin/accounts" \
  -H "Authorization: Bearer $ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"username":"customer_001","mailbox_domain":"mail.yahoohh.chat"}'
```

将返回 JSON 中的 **`api_key`** 与 **`mailbox.full_address`** 交给顾客即可。

### 3.5 常见错误

| HTTP | 含义 |
|------|------|
| 400 | `mailbox_domain` 对应域名不存在或未激活；或 JSON 不合法。 |
| 401 | 管理员 Key 无效。 |
| 403 | 非管理员 Key。 |
| 409 | `username` 已存在。 |

## 4. 顾客侧怎么用？

1. 打开你的 TempMail 网页（例如 `https://你的域名:8880` 或反代后的地址）。
2. 在登录页粘贴你交付的 **`api_key`**（**不是**管理员 Key）。
3. 进入 **邮箱总览**，即可看到**本次为其创建**的临时邮箱；点击进入 **查看邮件** 即可接收验证码或登录链接。

说明：系统**没有**「用邮箱地址 + 密码单独登录某一个邮箱」的设计；登录身份永远是 **TempMail 账户的 `api_key`**。

---

## 5. 管理后台里「创建账户」与 API 的差异

在网页 **账户列表 → 创建账户** 时，当前界面**仅发送用户名**（及可选「设为管理员」勾选，后端创建接口以实际 API 为准），**不会**传 `mailbox_domain`。

因此：

- **仅点网页「创建账户」**：得到新用户和 `api_key`，**不会**自动出现接码邮箱；需该用户登录后自行 **新建邮箱**，或你再用**该用户的 Key** 调 `POST /api/mailboxes` 代建。
- **需要「账号 + 现成邮箱」一条龙**：请使用上文 **`POST /api/admin/accounts` + `mailbox_domain`**，或用仓库内脚本（见下节）。

若你希望网页创建账户时也支持填写「默认域名并自动建邮箱」，需要再改前端表单与 `createAccount` 请求体，与本文后端能力对齐。

## 6. 本仓库附带的 Python 自测脚本

路径：`scripts/test_admin_create_account_with_mailbox.py`

- 默认示例中可配置 `DEFAULT_ADMIN_KEY`、`DEFAULT_MAILBOX_DOMAIN`（仅本机调试用）。
- **勿**将含真实管理员 Key 的脚本推送到公开 Git。

运行前请根据环境安装 Python 3，在项目根目录执行：

```bash
python scripts/test_admin_create_account_with_mailbox.py
```

可通过环境变量覆盖：`TEMPMAIL_ADMIN_KEY`、`TEMPMAIL_BASE`、`TEMPMAIL_MAILBOX_DOMAIN`、`TEMPMAIL_NEW_USERNAME`。

另：`scripts/test_create_mailbox.py` 用于在**当前 Key 所属账户**下测试 `POST /api/mailboxes`（与「新用户 + 专属邮箱」场景不同）。

## 7. 公开注册 `POST /public/register` 说明

公开注册**仅**创建平台账号并返回 `api_key`，**不会**自动创建邮箱（避免与「仅注册、自建邮箱」场景混淆）。

批量接码零售场景请优先使用 **`/api/admin/accounts` + `mailbox_domain`**。

---

## 8. 安全建议

- 管理员 Key 具备最高权限，**不要**写入给顾客看的文档或客户端。
- Key 一旦泄露，应在服务端轮换并更新所有自动化脚本。
- 生产环境建议用环境变量或密钥管理注入 Key，避免硬编码在仓库中。
